# Contributing to Inspiration Hub

Thanks for helping grow this collection! You don't need to be an expert — if you found something useful or inspiring, it probably belongs here. First-time contributors are very welcome.

## How the repository is organized

- Each **category** is a folder (for example, `AI/`).
- Each category's `README.md` lists its **topics**.
- Each topic is its own file (for example, `AI/papers-and-research.md`), and that's where entries go.

## How to contribute

1. **Fork the repository** using the "Fork" button at the top of the GitHub page.
2. **Find the right topic file** by opening a category folder and choosing the best-fitting topic (for example, `AI/models-and-tools.md`).
3. **Add your resource** using the format below, in its alphabetical place in the list.
4. **Commit your change** with a short message, such as `Add Hugging Face to AI`.
5. **Open a pull request** with a brief description of what you added and why it's useful.

Prefer not to use Git? You can edit any file directly on GitHub (click the pencil icon). GitHub will fork the repo and create the pull request for you.

## Entry format

```markdown
- **[Resource Name](https://example.com)** – A short, one-line description of why it's useful.
```

- Keep descriptions to one sentence.
- Use the resource's official link where possible.

## Keep everything alphabetical

Keep entries in every list **sorted alphabetically by name (A → Z)**. The same applies to topic tables in category READMEs. It makes things easy to scan and helps spot duplicates.

## Adding a new topic

If no existing topic fits:

1. Create a new file in the category folder, named in lowercase with hyphens (e.g. `Design/color.md`). Copy an existing topic file as a template.
2. Add a row for it to that category's `README.md` table, in alphabetical order.

## Guidelines

- **Avoid duplicates.** Search the repository (press `t` or use the search bar on GitHub) before adding.
- **Keep it relevant.** Share things that are genuinely useful or inspiring, not self-promotion or spam.
- **One topic per pull request.** Smaller pull requests are easier to review and merge quickly.
- **Keep it simple.** Plain Markdown only; no badges or images needed.

## Not sure where something belongs?

Put it where you think it fits best and mention it in your pull request. We'll figure it out together. Questions and suggestions are also welcome as issues.
